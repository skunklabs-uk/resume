# LinkedIn Query Seeds

## Principi
- Ogni query deve essere un titolo o alias preciso, con al massimo un contesto mirato.
- Le role family servono per analisi e calibrazione; gli alert devono restare stretti.
- Preferire seed separati per lingua e per stack quando il titolo da solo e ambiguo.
- Aggiungere contesto solo per disambiguare: Kubernetes, AWS, cloud, AI, fintech, banking, pre-sales.
- Non usare query generiche come `IT`, `software`, `cloud`, `AI`, `manager` o `lead` da sole.
- Quando una query mescola due mercati, splittarla invece di allargarla.
- Non inventare volumi: la calibrazione deve seguire solo il feedback osservato.

## CTO / Fractional CTO / Technical Co-founder
Intento: intercettare ownership tecnica di strategia, roadmap, prodotto e piattaforma in contesti startup, scaleup o nuove iniziative.

Query seed:
- `CTO`
- `"Chief Technology Officer"`
- `"Fractional CTO"`
- `"CTO frazionale"`
- `"Technical Co-founder"`
- `"Co-founder tecnico"`
- `"Direttore Tecnico"`
- `"Responsabile Tecnico"`
- `"Responsabile tecnologia"`

Segnali per calibrare:
- Tenere se gli alert mostrano ownership reale di architettura, team, roadmap, budget o prodotto.
- Splittare se `CTO` mescola ruoli IT operativi, vendor management o titoli executive senza delivery.
- Restringere se arrivano troppi annunci junior, consulenziali o puramente amministrativi.
- Ritirare se il titolo produce quasi solo ruoli con perimetro non tecnico o non decisionale.

## Query Da Evitare
- Query troppo larghe: `IT`, `software`, `technology`, `cloud`, `AI`, `data`, `manager`, `lead`, `architect`.
- Query di ruolo senza contesto quando il titolo e ambiguo: `Responsabile`, `Direttore`, `Head`, `Senior`, `Principal`.
- Query che fondono mercati diversi in un solo alert: `DevOps cloud AI`, `engineer manager architect`, `innovation transformation cloud` senza titolo preciso.
- Query orientate al rumore: `job`, `vacancy`, `hiring now`, `urgent`, `immediate start`.
- Query commerciali pure o troppo lontane dal target: `account`, `sales`, `vendor management`, `presales` da sole.

## Ciclo Di Calibrazione
1. Avviare ogni query stretta con uno solo o pochi alias precisi.
2. Dopo i primi alert, classificare ogni risultato in quattro esiti: keep, split, narrow, retire.
3. Keep: la maggioranza degli annunci e nella stessa family, con responsabilita e stack coerenti.
4. Split: la query mescola due mercati diversi, per esempio platform vs presales, oppure people management vs technical leadership.
5. Narrow: la query produce troppi falsi positivi, junior, recruiting generico o ruoli troppo lontani dal perimetro.
6. Retire: la query non produce piu segnali utili o restituisce quasi solo rumore.
7. Non allargare mai una query prima di aver capito perche il segnale e scarso o rumoroso.
8. Conservare le query che mostrano fit chiaro anche se il volume e basso; la scarsita da sola non basta per ritirarle.
